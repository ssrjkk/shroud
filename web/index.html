Shroud is an app chain where data never leaves its owner's device in cleartext. Buyers escrow a budget, nodes execute training over ciphertext, prove the work with a STARK, and settle through streaming payment channels.

The pipeline

Plaintext is encrypted in the browser. From that point on nothing on the chain, and nothing in a node's memory, ever holds it.

Compute on encrypted data

ZK proved what was computed. FHE removes the need to reveal the input at all. That is the difference between proving a result and never having to expose a row.

Proof of compute

Each epoch is pinned by a STARK public input binding the chain, task, dataset root and prior weights. A registered node can re-execute and report a different digest; a quorum of three distinct reporters rejects the epoch and pays nobody.

Streaming payments

PaymentVault settles in slices via EIP-1271, so contributors and nodes are paid as epochs land. An unredeemed remainder can be reclaimed by the node itself.

Properties that are actually enforced

Every row below is checked by a test. The rows that are not enforced are on the security page instead of being quietly omitted.

  • FHE end-to-end

    Input rows are encrypted client-side and never decrypted. Final weights are committee-revealed after settlement.

  • Explicit budgets

    createTask(budget, params) escrows exactly what the buyer names — no more.

  • Settlement always completes

    Paying every contributor in one call measured ~584M gas against a 30M block limit, so settleFrom(taskId, cursor) pages at 200 per call.

  • Disclosure is attested

    A task only reaches Disclosed once the committee has submitted threshold distinct partial decryptions. The buyer cannot shortcut the ceremony.

  • Key rotation cannot lie

    NetworkParams binds a candidate to its hash at proposal time and re-validates at execution, so the struct that was checked is the struct that lands.

  • The verifier cannot be swapped instantly

    Propose → 7-day timelock → execute, with permissionless execution so a queued rotation cannot be frozen by a compromised owner.

Three things that are not true yet

A protocol that moves money should tell you where it is soft. These are the ones that matter.

not enforced

The dispute quorum is not Sybil-resistant

registerNode is permissionless and takes no stake. The quorum is a flat count of three registered addresses, so a ring of three cheap addresses can deny a node its reward. It cannot steal it.

not implemented

No contribution bond, and no on-chain STARK check

Sybil row-farming is mitigated only by sqrt(rows) weighting plus one shard per address. Verification is sampled on chain and completed off-chain.

residual

A committee majority can decrypt user rows

This is documented as residual F-10 and is a property of the threshold scheme, not a bug to be patched later.
