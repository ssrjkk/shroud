What is enforced.
And what is not.

This protocol moves funds. Anyone can write a security section that is all green, and it would be worthless. So this page lists the rows that fail, with the same prominence as the ones that pass. If you are deciding whether to trust this with value, read the red section first.

Not enforced

These are the ones that would bite you.

not enforced

The dispute quorum is not Sybil-resistant

registerNode is permissionless and takes no stake. The quorum is a flat count of three distinct registered addresses, so three cheap addresses can deny a node its reward for an epoch. It cannot steal the reward, and it cannot accept a dishonest one — only refuse an honest node.

Threat model F-01, F-19 · limitations §2a

not enforced

Participants cannot detect a substituted FHE public key

NetworkParams pins the key correctly on chain, but nothing reads it. The SDK has no reference to s_pub, and the node's enforce_key_pin flag is dead code. A malicious sequencer can swap the key and harvest ciphertexts undetectably. The on-chain history does allow forensic detection afterwards.

Threat model F-08

not implemented

No slashable contribution bond

Fake-row farming is mitigated only by sqrt(rows) weighting plus one shard per address. There is no bond anywhere in the tree. An earlier version of the threat model claimed otherwise and has been corrected — a claim in a security doc that the code does not support is worse than no claim.

Threat model F-01 · limitations §2

not implemented

The chain does not fully verify the STARK

Verification is sampled on chain and completed off-chain. On-chain sampling bounds cost, not trust: a prover that passes sampling still owes the network an off-chain check.

limitations §3

residual, by design

A committee majority can decrypt user rows

This is a property of the threshold scheme rather than a bug. A majority of the decryption committee can reconstruct the plaintext; the scheme protects against a minority, not against collusion.

Threat model F-10

Enforced and tested

Each of these has a test that fails without the fix.

  • Escrow accounting is internally consistent

    PaymentVault asserts totalLocked == subBalancesTotal + channelLocksTotal on every balance movement, and the check is O(1).

  • A reentrancy guard covers the money path

    Tested with a hostile token that calls back mid-transferFrom.

  • Buyers cannot take funds owed to others

    settle and reclaimUnspentEpochs draw from disjoint pools, and reclaim reserves the contributor and committee shares.

  • Nothing is stranded by abort

    The work-in-progress slice is only withheld when a node actually verified an epoch, and it is paid as a redeemable channel rather than burned.

  • The winner's digest is the dispute target

    A losing committer cannot redirect the dispute and get an honest epoch rejected for free.

  • Re-executors are paid

    reexecutionBps of the disputed lock is split between the reporters, so disputing is rational rather than free.

  • Disclosed means the committee decrypted

    withdraw requires the gate to have reached threshold; the buyer cannot shortcut the ceremony.

  • The SDK cannot upload cleartext by omission

    Encryptor.providesConfidentiality is required, and the NoopEncryptor default is refused unless allowUnencrypted is set explicitly.

  • The DA client treats CIDs as hostile

    CIDs come from on-chain data any contributor controls, so they are validated before entering a request path; responses are size-capped and timed out, and getVerified re-hashes bytes against the on-chain ctDigest.

  • Parameter rotation installs exactly what it validated

    The candidate is bound to its hash at proposal time and re-validated at execution, so the struct that was checked is the struct that lands.

  • The payout-gating verifier cannot be swapped instantly

    Propose → 7-day timelock → execute, with permissionless execution so a queued rotation cannot be frozen by a compromised owner.

  • The surface does not imply guarantees that don't exist

    Unreachable declarations that implied missing mechanisms — a slashable bond, a rejected-contribution event, a finalize step that never ran — were removed rather than left to be misread.

Known issues worth knowing

known issue

The devnet deployment is broken with the pinned plugin

hardhat run does not install the FHE mock coprocessor, so CipherTask's constructor reverts with no reason; and the plugin refuses to deploy to a standalone hardhat node (Provider type mismatch). deploy.ts detects both and prints the diagnosis instead of a bare revert. The contracts are still fully exercised by the test suite.

Threat model F-31

deferred

Segmented proofs are documented as reachable but are not

No segmented proof implementation exists in the tree. The docs now say so rather than describing a mechanism that is not there.

Threat model F-33

protocol change needed

Immature channels shrink the contributor pool at settlement

Contributors that never redeem are reclaimed only at settlement, so a task at its contributor cap can end each epoch with too few contributors to settle. This needs a protocol change, not a patch.
